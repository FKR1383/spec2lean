## Proposed scope

Scope ID `PTX_9_3_BOUNDED_SCALAR_B32_REGISTER_PREDICATE_CORE` means: scalar `.b32` units whose bounded syntax reads ordinary value registers or immediate bit values, optionally reads one predicate guard, and whose modeled effects are confined to an ordinary destination-register update or no update.

It excludes memory and address-space effects; special/parameter/address/function/kernel registers; atomics, barriers, concurrency, calls and control transfer; vector/packed/matrix/tensor and non-`.b32` forms; and implicit carry, flags, status, rounding, saturation, or exception state. A unit outside these conditions must receive deeper review or use the legacy path. Instruction-specific bit-bucket legality is explicitly excluded.

## Consequences of approving this shared environment

For a future OpenCode run that both matches the production profile and passes the scope eligibility checks, the semantic extractor may reuse these nine hash-bound entries without regenerating or re-reviewing their content at Gate B. It may treat `.b32` as an exact 32-bit untyped bit domain, use the bounded value/predicate register model and partial lookup convention, and reuse the general predication evidence plus the reviewed false-guard no-transition derivation. It may also cite the general bit-bucket rule only as a conditional PTX fact.

OpenCode must still reason about and produce the instruction-specific delta: exact syntax and operand order; legal register/immediate forms; operand type compatibility; the operation; reads, writes, aliasing and read-before-write; modifiers; preconditions; version/target restrictions; exceptional/undefined/implementation-defined behavior; proof families; and any assumptions or open questions. In particular, bit-bucket applicability remains instruction-specific. Any excluded feature, uncertain state effect, source contradiction, unresolved state-affecting question, invalid delta, or critic request for broader context must trigger deeper review or the legacy full-semantic fallback.

Approval would authorize reuse only for this environment revision and hash. It would not modify any accepted unit, approve any future unit, approve Gate B for a run, or make the three design dependencies NVIDIA source facts.
