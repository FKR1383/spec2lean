# Semantic environment and instruction delta IR

This directory defines Performance Architecture v2's semantic composition
contract. It separates a versioned, human-reviewed language environment from
the instruction-specific semantic delta generated by an OpenCode agent.

The schemas are:

- `shared-environment.schema.json`: reusable semantic entries, official
  evidence, an explicit eligibility/exclusion scope, content fingerprints,
  accepted-unit support, entry review state, and lifecycle metadata;
- `instruction-delta.schema.json`: unit identity, explicit shared references,
  local claims and evidence, refinements, syntax, operands, operation, state
  effects, preconditions, and proof families;
- `common.schema.json`: the five claim classifications, evidence records,
  fingerprints, and claim lifecycle.
- `semantic-profile.schema.json`: bounded fast-path capabilities, mandatory
  safety checks, required approved shared IDs, and explicit legacy fallback.

The TypeScript equivalents and deterministic implementation are under
`engine/orchestrator/src/semantic-ir/`.

## Authority and review

`SOURCE_FACT`, `DERIVED_INTERPRETATION`, `DESIGN_DEPENDENCY`, `ASSUMPTION`,
and `OPEN_QUESTION` remain distinct values throughout validation,
materialization, and critic-packet construction. A source fact requires an
existing official HTML or PDF evidence record. A delta-local source fact also
requires `sourceBundleEvidenceId`, pinning it to an exact fragment in the
bounded Source Curator artifact. An assumption requires an
explicit human-approval dependency. Mechanical validation never upgrades a
classification or implies semantic approval.

Both the environment and each shared entry carry review state. Production
materialization requires `HUMAN_APPROVED` by default. Entry provenance retains
the originating artifact and review-record hashes and binds each prior
accepted unit to exact evidence IDs and approval records, while evidence records pin
the source document and source manifest. Changing semantic content or any of
those fingerprints changes the canonical environment hash and invalidates a
delta's pin.

Lifecycle values (`ACTIVE`, `SUPERSEDED`, and `INVALIDATED`) make replacement
and invalidation explicit. Deltas refer to stable semantic IDs and a precise
environment ID, revision, and hash.

## Deterministic composition

The materializer validates both inputs, resolves transitive dependencies of
explicit shared references, and emits claims and evidence in stable order.
Shared claims, delta claims, and refinements retain different `origin` values;
an override therefore never silently rewrites an official source fact.
Semantically unordered arrays are normalized before hashing, so source-array
permutations produce the same hash and materialized view.

An active, state-affecting `OPEN_QUESTION` remains structurally reviewable but
is returned in `unresolvedStateAffectingSemanticIds`. The CLI treats that list
as blocking even when the document is otherwise structurally valid.

## Commands

From the repository root:

```bash
./spec2lean semantic-ir validate-shared <environment.json>
./spec2lean semantic-ir validate-delta <environment.json> <delta.json>
./spec2lean semantic-ir materialize <environment.json> <delta.json>
./spec2lean semantic-ir review-packet <environment.json> <delta.json>
./spec2lean semantic-ir hash-shared <environment.json>
```

`approve-shared` is a separate human action. It validates and hash-binds the
configured review candidate and packet, derives the approved copy without an
LLM, and atomically activates that copy in the semantic profile. Validators
and self-tests never invoke it.

`review-packet` emits the compact, classification-grouped input intended for
incremental Semantic Critic integration. It includes a deterministic full-view
fallback reference; the existing full critic path has not been removed.

The committed fixtures under `tests/fixtures/semantic-ir/` use the accepted
`and.b32` artifacts read-only. Their semantic statements are explicitly
non-authoritative test data and do not create shared PTX approval.
