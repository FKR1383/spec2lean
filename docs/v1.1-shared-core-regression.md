# V1.1 shared-core regression

The V1.1 stabilization regression used three existing PTX 9.3 units from plan
`plan:50019c3a2e881d339fdede3d`: `sub.u32`, `mul.lo.u32`, and `shl.b32`. This is
only a real-data regression for the language-independent mechanism; no PTX
concept or representation is built into Spec2Lean.

Fresh Phase-1 through Phase-4 artifacts were reused in a temporary workspace.
Their copied Phase-4 payloads were migrated to semantic schema v2 and explicitly
linked to two request-bounded shared prerequisites: a 32-bit value domain and a
destination-oriented execution context. All three migrated artifacts passed the
current deterministic Phase-4 validator before Phase 5 ran.

The live external-model attempt was not authorized to export the local plan and
semantic artifacts, so the regression used a deterministic local MCP session
harness. The harness exercised the production shared-core and group-translation
submission validators, immutable store, manifests, hash bindings, Lean build,
and Phase-6 checks without external data egress. Generic automated tests cover
the same paths with specification-neutral synthetic data.

## Before and after

Before V1.1, the two generated group files contained 11 infrastructure
declarations. Five concepts were duplicated across both groups (`U32`, `Carry`,
`Predicate`, `Register`, and `MachineState`), leaving five redundant second
copies. `U32` conflicted (`Fin (2 ^ 32)` versus `BitVec 32`) and `MachineState`
had incompatible fields and register accessors. The files compiled separately,
but their value and state APIs were not composable.

After V1.1, one frozen core contained four declarations: `Value32`, `Register`,
`MachineState`, and `write`. Neither group declared local value/state
infrastructure, so duplicate shared declarations and conflicting
representations both fell to zero. Infrastructure fell from 11 declarations to
4 (7 fewer, about 64%); unused `Carry` and `Predicate` aliases were not retained.
The unit files retained only four integer-arithmetic declarations and three
shift declarations.

Both group manifests referenced the exact same `coreRunId`, source hash,
manifest hash, and Lean module. All three units passed BUILD, COVERAGE, and
TRACEABILITY. A combined Lean module imported both groups and typechecked a
cross-group composition from `mul_lo_u32` into `shl_b32` using the one shared
`Value32` type under Lean 4.33.1.

The unit-specific subtraction, low-product, clamped-shift, and destination-write
behaviors and their claim coverage were retained. V1.1 deliberately changed
their representation boundary; it did not add a proof of semantic equivalence.
The shared declarations remained traceable through dependency IDs and current
Phase-4 claim references, and the second core request reused the frozen snapshot
without invoking another materializer session.
